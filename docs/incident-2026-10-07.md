# Отказ основного VPS — 7 октября 2026

Основной VPS vm-11745 (31.76.244.26) выключен за неоплату по уведомлению
провайдера, переданному владельцем. SSH не отвечает. Сам по себе сетевой
таймаут не доказывает выключение.

## Почему не было автоматического переключения

Автоматическое продвижение резерва и DNS failover не были реализованы.
Ansible настраивал резервные копии, наблюдение и локальное восстановление.
Монитор намеренно не запускал второй worker по одному сетевому сбою.
Это незавершённая отказоустойчивость, а не успешно работающий failover.

## Что ещё обязательно завершить

1. Проверить распространение всех DNS-записей и выпуск HTTPS для домена.
2. Проверить дальнейшие уведомления: монитор переключён на активное приложение.
   Старые копии бывшего primary больше не считаются копиями активной базы.
   Отсутствие независимой регулярной копии остаётся отдельной тревогой.
3. Организовать регулярную независимую копию нового активного сервера.
   Разовый локальный dump не заменяет автоматическое резервирование.
4. Обновить inventory, deploy guards и CI/CD для новой активной роли.
   Локальный Ansible guard уже запрещает применение старой роли reserve
   к ACTIVE; это защитный отказ, а не законченная перенастройка.
5. Для безопасного автоматического failover нужен второй доступный узел,
   проверяемое fencing и программный DNS-доступ. Текущий VPSPay ключ не
   управляет прежним узлом; его нельзя считать выполненным fencing.
6. Старый VPS нельзя включать с прежними workers: сначала изоляция запуска,
   синхронизация актуальной базы с нового рабочего и проверка единственного
   активного publisher. Автоматического failback нет.
