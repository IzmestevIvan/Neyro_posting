# Загрузка внешнего содержимого

## Политика

`app/sources/safe_http.py` используется для статей, RSS и изображений водяного знака. Разрешены HTTP и HTTPS на портах 80/443, без userinfo и IPv6 zone ID. Loopback, private, link-local, multicast, unspecified и неглобальные адреса запрещены. IPv4-mapped IPv6, 6to4 и Teredo также отклоняются.

Каждое новое TCP-соединение разрешает DNS внутри PublicNetworkBackend. Проверяются **все** ответы; наличие запрещённого адреса отменяет соединение. Сетевой backend получает только проверенный числовой IP. Исходный hostname остаётся в HTTP Host и TLS SNI, сертификат проверяется стандартным SSL-контекстом. Это устраняет повторное разрешение исходного домена между проверкой и подключением. Proxy-переменные окружения не используются.

Редиректы обрабатываются вручную, до четырёх переходов. Каждый адрес проходит ту же политику. Общий deadline 30 секунд включает DNS, соединение, редиректы и чтение; сетевые операции дополнительно ограничены 10 секундами. Объём контролируется как по Content-Length, так и по реально прочитанным чанкам: 2 MiB для статей/RSS, 8 MiB для изображения.

Серверу отправляется Accept-Encoding: identity. Любое другое Content-Encoding отклоняется до чтения тела: автоматическая распаковка не выполняется. Это может исключить источники с некорректной поддержкой identity. Статьи принимают HTML/XHTML/plain text; ленты — RSS/Atom/XML/plain text; изображения — JPEG/PNG/WebP/GIF. Отсутствующий или неподходящий Content-Type отклоняется.

Feedparser получает уже загруженные bytes и не выполняет собственные сетевые запросы. Водяной знак сохраняет прежнее поведение при ошибке — возвращает None, но журнал содержит только тип исключения, без исходного URL и его параметров.

## Зависимости и проверка

httpcore закреплён на 1.0.9: адаптер использует внутренний AnyIOBackend. Обновление этой зависимости требует проверки backend API, DNS pinning и настоящего HTTPS-запроса. httpx остаётся 0.28.1.

`tests/test_safe_http.py` проверяет запрещённые адреса, смешанные DNS-ответы, подключение к числовому IP, приватный/относительный redirect, предел переходов, Content-Length, поток без указанного размера, сжатие, тип содержимого, общий deadline и передачу bytes RSS-парсеру.

## Границы

Это политика трёх указанных путей загрузки, не сетевой firewall всего приложения. Telegram API, Gemini и фиксированный Telegram preview имеют отдельные клиенты. Лимит пикселей после декодирования изображений, ограничение CPU парсера и настройка сетевого egress на VPS остаются отдельными задачами. Не следует считать ограничение байтов защитой от всех декомпрессионных изображений.
