# HTTP API

База — `/api`. Формат — JSON. Ошибки возвращаются как `{"detail": "текст по-русски"}`
и показываются в панели тостом, поэтому тексты пишутся для конечного пользователя.

## Авторизация

Каждый запрос несёт заголовок `X-Init-Data` со строкой `initData` из Telegram Web App.
`app/api/auth.py:verify_init_data()` проверяет её по алгоритму Telegram:

1. из строки вынимается `hash`;
2. остальные пары сортируются по ключу и склеиваются через `\n`;
3. `secret = HMAC-SHA256("WebAppData", BOT_TOKEN)`;
4. `HMAC-SHA256(secret, data_check_string)` сравнивается с `hash` через `compare_digest`;
5. `auth_date` не старше 24 часов.

Пользователь заводится в базе при первом успешном запросе. Заблокированный (`users.blocked`)
получает 403.

**Режим отладки.** При `DEV_AUTH=1` принимается заголовок `dev:<tg_id>` без подписи.
Это дыра по определению — любой подставит чужой ID. В `.env` на сервере переменной нет,
и так должно оставаться; проверить можно запросом снаружи:

```bash
curl -s -H "X-Init-Data: dev:1" https://<хост>/api/bootstrap   # ожидаем 401
```

| Код | Когда |
|---|---|
| 401 | нет подписи, подпись не сошлась, сессия старше суток, испорченный `auth_date` |
| 402 | доступ не активирован или истёк — панель показывает экран промокода |
| 403 | пользователь заблокирован; чужой канал; не админ; превышен лимит каналов по тарифу |
| 404 | канал, источник или пост не найдены |
| 409 | пост уже публикуется или опубликован |
| 429 | исчерпан дневной лимит |
| 502 | Telegram или Gemini не ответили |
| 503 | на сервере не задан `BOT_TOKEN` |

## Доступ

Ручки, работающие с каналами, зависят от `active_user` — он требует действующий промокод.
`/bootstrap` и `/promo/redeem` намеренно открыты для любого опознанного пользователя:
панель должна уметь показать экран ввода кода.

### `GET /bootstrap`
Всё, что нужно панели при старте: профиль (`is_admin`, `has_access`, `access_until`,
`daily_limit`, `max_channels`, `promo_code`), список **своих** каналов со всеми
настройками, справочники языков, часовых поясов, режимов задержки и темпа, а также
`bot_username` для экрана подключения.

### `POST /promo/redeem` — `{"code": "ABCD-2345"}`
Активирует код: проставляет пользователю лимиты и срок. Регистр и дефис не важны —
`normalize()` приводит ввод к канону. Свой же код продлевает доступ, чужой активированный
даёт 400.

## Каналы

### `POST /channels` — `{"ref": "@канал"}`
Резолвит канал через `bot.get_chat()`. Если бот не админ — 400 с объяснением. Принимает
`@name`, `t.me/name`, `https://t.me/name` и ссылку на конкретный пост.

### `PATCH /channels/{id}`
Принимает только поля из белого списка `_clean_settings()`. Всё остальное игнорируется,
и если после фильтрации ничего не осталось — 400. Имена колонок никогда не приходят из
запроса напрямую: ключ сначала должен совпасть с известным, и только потом попадает в SQL.

Значения нормализуются: булевы — в 0/1, перечисления сверяются со справочниками,
`digest_time` — по маске `ЧЧ:ММ`, `window_start` зажимается в 0–23, `window_end` в 1–24,
свободный текст обрезается до 4000 символов.

Включение «Голоса канала» дополнительно подтягивает примеры постов самого канала.

### `DELETE /channels/{id}`
Каскадом удаляет источники и посты канала.

### `GET /channels/{id}/stats`
Числа для главного экрана. Пожизненные счётчики берутся из `stats_daily`, очередь — из
`posts`. Плюс графики за 7 дней, показатели системы (CPU, RAM), текущая активность
воркера и остаток паузы основной модели.

### `GET /channels/{id}/feed`
До 30 постов в статусе `pending` с текстом, медиа и вердиктом фактчека.

### `GET /channels/{id}/history`
Последние 50 постов не в модерации — с причиной, по которой они были отсеяны.

### `POST /channels/{id}/publish_now`
Берёт ближайший готовый пост (сначала `approved`, потом `pending`) и публикует немедленно.
Если готовых нет — 404 с подсказкой дождаться новых.

## Посты

### `POST /posts/{id}/approve`
Публикует. Захват строки атомарный, повторное нажатие даёт 409, а не второй пост в канале.

### `POST /posts/{id}/reject`
Переводит в `rejected`.

### `POST /posts/{id}/regen`
Прогоняет исходный текст через конвейер заново и возвращает новый вариант.

## Источники

### `GET /channels/{id}/sources`
Список с заголовком, типом, медианой просмотров и текстом последней ошибки.

### `POST /channels/{id}/sources` — `{"ref": "..."}`
Тип определяется автоматически: адрес не на `t.me` — это RSS, иначе Telegram-канал.
Источник сразу проверяется живым запросом; недоступный не добавляется.

### `DELETE /sources/{id}`
Проверяет владельца канала, к которому привязан источник.

## Рекламодатели

### `GET /channels/{id}/ads`
Отсеянная реклама: имя рекламодателя, распарсенные контакты, причины отсева, сколько раз
это предложение встречалось. Архивные записи не отдаются.

### `POST /ads/{id}/{status}`
`new` · `contacted` · `archived`.

## Админка

Только для `users.is_admin` или ID из `ADMIN_IDS`.

### `GET /admin/overview`
Пользователи с числом каналов и лимитами, все каналы с числом источников и режимом,
суммарные счётчики и остаток паузы модели.

### `POST /admin/users/{tg_id}` — `{"daily_limit": 1000}` или `{"blocked": true}`

### `GET /admin/promo`
Все коды с тарифом и тем, кто их активировал.

### `POST /admin/promo` — `{"count": 5, "plan": "pro", "note": "…"}`
Выпускает до 100 кодов за раз. Тарифы — `start`, `pro`, `unlim`.

### `DELETE /admin/promo/{code}`
Удаляет только неактивированный код.

## Прочее

- `GET /healthz` — `{"ok": true}`, используется healthcheck-ом контейнера.
- `GET /` — HTML панели, `GET /static/*` — её ассеты.
