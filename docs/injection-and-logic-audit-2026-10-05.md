# Аудит логики, SQL и prompt injection — 5 октября 2026

## Исправления

- Потеря курсора источника больше не ограничивает восстановление последними пятью
  новостями: обрабатывается вся уже загруженная ограниченная страница. Возраст,
  рабочее окно и сохранённые UID по-прежнему исключают старые материалы и дубли.
- Будущая дата не продвигает курсор и не скрывает сегодняшнюю новость при первом
  подключении. Когда дата наступит, материал можно обработать штатно.
- После сетевой загрузки повторно проверяются источник (включённость, адрес,
  тип, канал, курсор) и текущие настройки канала под блокировкой строк.
- Короткие новости при ручном режиме попадают в проверку, а не в неотправляемый
  дайджест. Отключение дайджеста/автопубликации возвращает уже подготовленные
  соответствующие материалы в ручную проверку.
- Дайджест повторно проверяет настройки и неизменность исходников/текстов после ИИ;
  отключение режима, изменение языка/тематики или правка участника отменяют сборку.
- Незавершённый или заблокированный ответ Gemini не принимается как готовый пост.
  Служебные reasoning parts исключены. JSON должен быть объектом без повторных
  ключей, NaN/Infinity и постороннего текста вокруг JSON.

## SQL

Проверенные запросы используют параметры asyncpg. Пользовательские значения,
тексты источников и результаты ИИ не подставляются в SQL. В двух динамических
обновлениях API введён независимый фиксированный список таблиц и полей: расширение
валидации HTTP само по себе не разрешает новое SQL-поле. Остальные динамические
фрагменты — константы приложения (DDL миграций, очистка, публичные поля пула ключей,
фильтр архива рекламы); пользовательские строки в них не участвуют.

Регрессии на настоящем изолированном PostgreSQL проверяют сохранение вредоносной
строки буквально, неизменность соседнего канала и таблицы пользователей,
отклонение поддельного имени поля и попытки изменить owner_id/is_admin через helper.
Это усиление существующей параметризации, а не заявление о найденной ранее
эксплуатируемой SQL-инъекции.

Read-only проверка production подтвердила: роль `neyro_app` без superuser,
createdb, createrole, replication, bypassrls; нет членства в pg_read_server_files,
pg_write_server_files, pg_execute_server_program. Сохраняется владение таблицами
для миграций при запуске: полное разделение DDL/DML потребует отдельного выпуска
миграций и ротации роли. Не утверждать, что этот остаточный риск уже устранён.

## ИИ и недоверенные материалы

Системные правила явно отделены от JSON с исходниками, стилевыми примерами,
недавними постами, пожеланиями и ответом модели. Пожелания ограничены тематикой,
языком и оформлением; не дают права отключать проверки или назначать публикацию.

Локальные проверки перед моделью останавливают узнаваемые команды подмены правил,
ролей и извлечения секретов, в том числе часть Unicode-маскировки. Проверяется
полный вход до усечения для промпта. Отравленный пример истории исключается из
контекста, а не блокирует все будущие новости. На выходе запрещены узнаваемые
секреты, команды, ссылки и активная разметка. Правки и дайджесты проходят те же
границы; бизнес-генерация также защищена, но режим остаётся выключенным.

Подозрительный материал не становится готовым к публикации; исходник сохраняется
с причиной в истории. Проверки не отправляют вредоносные тесты в реальные каналы.
Модель не получает инструменты SQL/shell/отправки, ключи остаются в HTTP-заголовке;
доступ, лимиты и статусы доставки контролирует код сервиса.

Ограничения: это многоуровневая защита, не доказательство невозможности prompt
injection. Новые формулировки/кодировки могут обойти эвристику; статья, цитирующая
атаку, может быть остановлена ошибочно. JSON сам по себе не является изоляцией.
В режимах fast/balanced отдельного фактчека каждой новости по-прежнему нет.
Фактическая точность ИИ и внешние квоты остаются отдельными рисками.

Основание: [OWASP SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)
и [OWASP LLM Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html).
