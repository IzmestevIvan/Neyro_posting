# Эксплуатация

## Прод

VPS на Ubuntu 24.04 (1 vCPU / 2 ГБ), три контейнера в `/opt/neyro`:

- `db` — PostgreSQL 16, порт наружу не публикуется, доступен только из docker-сети;
- `app` — бот и API, слушает 8080 только внутри docker-сети;
- `caddy` — HTTPS на 80/443, сам получает и продлевает сертификат Let's Encrypt.

Панель: `https://<ip-через-дефисы>.sslip.io`. Домена нет — `sslip.io` резолвит IP из самого
имени, и Let's Encrypt спокойно выдаёт на него сертификат. Этот же адрес привязан к
кнопке меню бота (`setChatMenuButton`).

База — docker-том `pgdata`. Логотипы — `/opt/neyro/data`. Оба переживают пересборку образа.

## Переменные окружения

`.env` лежит только на сервере, права 600, в git и в образ не попадает.

| Переменная | Обязательна | Смысл |
|---|---|---|
| `BOT_TOKEN` | да | без неё процесс не стартует |
| `ADMIN_IDS` | да | ID через запятую, доступ к админ-панели |
| `GEMINI_API_KEY` | де-факто да | общий ключ; без него посты копятся в статусе `new` |
| `GEMINI_MODEL_MAIN` | нет | основная модель, по умолчанию `gemini-2.5-flash` |
| `GEMINI_MODEL_VERIFY` | нет | модель фактчека, по умолчанию `gemini-2.0-flash` |
| `GEMINI_MODEL_FALLBACK` | нет | резерв при квоте или сбое |
| `POSTGRES_PASSWORD` | да | пароль базы; `docker-compose.yml` собирает из него `DATABASE_URL` |
| `POSTGRES_USER`, `POSTGRES_DB` | нет | `neyro` / `neyro` |
| `DATABASE_URL` | локально да | строка подключения; в проде её задаёт compose |
| `SITE_ADDRESS` | да | домен для Caddy |
| `PUBLIC_URL` | да | HTTPS-адрес панели, уходит в кнопку Web App |
| `PORT`, `HOST` | нет | 8080 / 0.0.0.0 |
| `DEFAULT_DAILY_LIMIT` | нет | лимит новых пользователей, 500 |
| `POLL_INTERVAL` | нет | период опроса источников, 90 с |
| `DEV_AUTH` | **нет** | `1` отключает проверку подписи. Только локально, на проде переменной быть не должно |

Модели вынесены в переменные намеренно: линейка Gemini меняется чаще, чем этот код.
Смена модели — правка `.env` и `docker compose restart app`, без пересборки.

## Деплой

```bash
./deploy.sh
```

Перед отправкой скрипт прогоняет тесты. Адрес сервера берётся из `.deploy.env` (файл в
`.gitignore`, в репозиторий не попадает), `.env` на сервере не трогается.

При старте `db.connect()` прогоняет миграции — новые колонки добавляются в существующую
базу автоматически.

## Команды на сервере

```bash
cd /opt/neyro
docker compose logs -f app        # живой лог
docker compose logs app --tail 50
docker compose restart app        # после правки .env
docker compose ps                 # состояние и healthcheck
docker compose down               # остановить всё
```

Резервная копия базы:

```bash
ssh root@СЕРВЕР "docker compose -f /opt/neyro/docker-compose.yml exec -T db \
  pg_dump -U neyro neyro" > neyro-$(date +%F).sql
```

## Тесты

```bash
.venv/bin/python -m pytest tests/ -q
```

Нужен локальный PostgreSQL: тесты работают с базой `neyro_test` и чистят её перед каждым
тестом (`TEST_DATABASE_URL` переопределяет адрес). Сеть и Telegram не нужны: разбор
страницы проверяется на зафиксированном HTML, отправка — на подменённом боте. Проверять `docker compose ps` вместо
тестов бессмысленно: healthcheck отвечает `{"ok": true}` даже когда конвейер стоит.

## Диагностика

**Панель не открывается в Telegram.** Web App требует HTTPS. Проверить, что `PUBLIC_URL`
и `SITE_ADDRESS` совпадают с реальным адресом, а Caddy получил сертификат:
`docker compose logs caddy | grep certificate`.

**Панель показывает старую версию.** Telegram кеширует статику — закрыть и открыть
мини-приложение заново.

**Посты не появляются.** По порядку:

1. `docker compose logs app --tail 50` — ошибки опроса источников;
2. в панели «Источники» — красным подсвечены недоступные;
3. блок «Система» на главной — что воркер делает прямо сейчас и не стоит ли пауза модели;
4. «Отфильтровано» растёт, а публикаций нет — скорее всего слишком строгие стоп-слова,
   «только хиты» или «только с медиа»; история постов показывает причину для каждого.

**Ключ Gemini не задан.** В логе `не задан ключ Gemini`, воркер замолкает на 5 минут и
пробует снова. Посты не теряются — лежат в статусе `new` до появления ключа.

**Основная модель на паузе.** Ожидаемое поведение при 429. Остаток паузы виден в панели;
через 30 минут система вернётся на основную модель сама.

**Два процесса на одном токене.** Telegram отдаёт `terminated by other getUpdates
request`, бот перестаёт отвечать. Причина — локальный запуск при работающем сервере.
Держать нужно ровно один экземпляр.

## Безопасность

- Вход по SSH — только по ключу: `scripts/harden.sh` выключает парольную аутентификацию.
  Тонкость: `50-cloud-init.conf` включает пароли обратно, а sshd берёт **первое** вхождение
  директивы, поэтому наш файл называется `00-hardening.conf` и правит cloud-init.
- fail2ban банит на час после 4 неудачных попыток; автообновления безопасности включены.
- Наружу открыты только 22, 80 и 443 (ufw), у базы порт вообще не опубликован.
- Caddy отдаёт HSTS, CSP, `X-Content-Type-Options`, `Referrer-Policy` и `Permissions-Policy`.
- `.env` не в git (`.gitignore`), не в образе (`.dockerignore`), права 600.
- Контейнер `app` работает от непривилегированного пользователя (uid 10001).
- URL файлов Telegram содержат токен бота и поэтому не сохраняются — в базе лежит `file_id`.
- Ключ Gemini клиента хранится в базе открытым текстом и возвращается только владельцу
  канала. Если появятся сторонние клиенты, ключи стоит шифровать.
- Пароль root, токен бота и токен GitHub засветились в переписке при настройке. Вход по
  паролю отключён, но токены следует перевыпустить.
- Ключ деплоя — `~/.ssh/neyro_deploy`. Потеря ключа означает вход только через консоль
  хостера, поэтому стоит добавить на сервер второй, запасной ключ.

## Известные ограничения

- Дневной лимит считается по суткам **UTC**: для Москвы счётчик обнуляется в 3 часа ночи.
- `subscribers` и `avg_views` в пределах дня берутся по максимуму, то есть отток
  подписчиков внутри суток на графике не виден.
- `process_loop` обрабатывает посты последовательно; один медленный ответ Gemini
  задерживает очередь.
- Источниками могут быть только публичные Telegram-каналы с включённым предпросмотром.
- Водяной знак не накладывается на медиа, присланное боту в чат.
- Посты, отложенные в дайджест, останутся в статусе `digest`, если дайджест выключить,
  не дождавшись отправки.
