## Причины ночных уведомлений

Проверен промежуток с 00:00 МСК 8 октября до ~10:34 МСК.
Рабочие app/db healthy; support без ошибок в журнале; доступно около 1 GB RAM.
Монитор постоянно отмечал отсутствие независимой копии после вчерашней смены
ролей. Эта причина исправлена проверяемым offsite backup.
Остаётся необходимость плановой перезагрузки после security updates.
В журнале приложения преобладают HTTP 429 Gemini, встречается HTTP 503.
Переключение на запасную модель часто помогало, но часть материалов отложена
на 15 минут. Миграция VPS сама по себе квоты ИИ не увеличивает.

Подготовлен exponential backoff для отдельной пары ключ/модель: 429 начиная
с 120 секунд, 5xx с 30 секунд, до 30 минут; успех конкретной модели сбрасывает
её историю. Другие модели/ключи не блокируются. 16 выбранных тестов успешны.
Изменение пока НЕ установлено в рабочее приложение.

## Не завершено — не выдавать за готовое автопереключение

1. Fencing прежнего writer, единственный активный bot/support, перенос данных
   в синхронный Patroni-контур, маршрутизация БД и приложения, защита старой
   очереди от повторной отправки. Нужны испытания реального отказа и partition.
2. Резервирование самого распределителя: единственный третий узел не должен
   стать единственной точкой отказа. etcd-кворум уже подготовлен на всех трёх.
3. Автоматический DNS updater с ограничением на домен/адреса, проверкой здоровья
   и защитой от колебаний; снижение TTL (сейчас замечен кеш 21600 секунд).
4. Проверить default PostgreSQL/Patroni services перед reboot: staging не должен
   сам запустить лишний кластер. Работающий Compose сохраняется до миграции.
5. Старый site.yml/operations.yml рассчитан на legacy-группу reserve; после
   обновления inventory группа пуста. НЕ применять site.yml целиком до
   согласования ролей. Использовать отдельные ha-*.yml.
6. Требуется обновить CI/CD и слить изменения после проверок. GitHub CLI сейчас
   возвращает HTTP 401 Bad credentials через прежний credential helper.
   Не обходить проверку CI/подписи релиза прямой незаметной подменой кода.

Секреты, локальные копии и HA-пароли находятся в .recovery-private/ (gitignored).
Нельзя публиковать содержимое этого каталога, env-файла или /etc/neyro-ha.
