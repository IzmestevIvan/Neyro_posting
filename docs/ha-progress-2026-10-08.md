## Причины ночных уведомлений

Проверен промежуток с 00:00 МСК 8 октября до ~10:34 МСК.
Рабочие app/db healthy; support без ошибок в журнале; доступно около 1 GB RAM.
Монитор постоянно отмечал отсутствие независимой копии после вчерашней смены
ролей. Эта причина исправлена проверяемым offsite backup.
Остаётся необходимость плановой перезагрузки после security updates.
В журнале приложения преобладают HTTP 429 Gemini, встречается HTTP 503.
Переключение на запасную модель часто помогало, но часть материалов отложена
на 15 минут. Миграция VPS сама по себе квоты ИИ не увеличивает.

Подготовлен exponential backoff для отдельной пары ключ/модель: 429 начиная
с 120 секунд, 5xx с 30 секунд, до 30 минут; успех конкретной модели сбрасывает
её историю. Другие модели/ключи не блокируются. 16 выбранных тестов успешны.
Изменение пока НЕ установлено в рабочее приложение.

## Не завершено — не выдавать за готовое автопереключение

1. Fencing прежнего writer, единственный активный bot/support, перенос данных
   в синхронный Patroni-контур, маршрутизация БД и приложения, защита старой
   очереди от повторной отправки. Нужны испытания реального отказа и partition.
2. Резервирование самого распределителя: единственный третий узел не должен
   стать единственной точкой отказа. etcd-кворум уже подготовлен на всех трёх.
3. Автоматический DNS updater с ограничением на домен/адреса, проверкой здоровья
   и защитой от колебаний; снижение TTL (сейчас замечен кеш 21600 секунд).
4. Проверить default PostgreSQL/Patroni services перед reboot: staging не должен
   сам запустить лишний кластер. Работающий Compose сохраняется до миграции.
5. Старый site.yml/operations.yml рассчитан на legacy-группу reserve; после
   обновления inventory группа пуста. НЕ применять site.yml целиком до
   согласования ролей. Использовать отдельные ha-*.yml.
6. Требуется обновить CI/CD и слить изменения после проверок. GitHub CLI сейчас
   возвращает HTTP 401 Bad credentials через прежний credential helper.
   Не обходить проверку CI/подписи релиза прямой незаметной подменой кода.

Секреты, локальные копии и HA-пароли находятся в .recovery-private/ (gitignored).
Нельзя публиковать содержимое этого каталога, env-файла или /etc/neyro-ha.

## Проверка сети и репетиция переключения 8 октября

Обнаружена потеря крупных пакетов в WireGuard между Финляндией и Германией:
при MTU 1420 создание реплики зависало, TCP повторял передачу, малые пакеты
проходили. MTU снижен до 1280 на всех трёх узлах без перезапуска интерфейсов,
значение сохранено в конфигурации и Ansible-шаблоне. После перезапуска только
тестовой службы neyro-patroni на финском узле все реплики перешли в streaming
с нулевым отставанием. Рабочая Docker-база не перезапускалась.

ha-stage-check.yml выполнен успешно на всех узлах. Тестовые службы Patroni
теперь запущены, но автозапуск отключён. Это заменяет предыдущую отметку
о неактивных службах выше.

ha-stage-failover.yml выполнен успешно: остановлена отдельная тестовая база
на neyro_de, автоматически избран neyro_witness, контрольная запись сохранена.
Бывший лидер запущен обратно и прошёл healthcheck. Рабочий /healthz отвечал ok.
Это репетиция остановки процесса базы, НЕ отключения всего VPS и НЕ проверка
переноса рабочего бота, платежей, DNS или защиты от сетевого разделения.

Проверка портов с другого VPS: публично доступны 22/80/443; PostgreSQL,
etcd, Patroni и Docker API по публичным адресам недоступны. Результат проверки
с локального компьютера был искажён сетевым посредником, поэтому перепроверен.

Исправлена локальная проверка роли в службах восстановления и выпуска:
наличие старого каталога резерва не блокирует узел с маркером ACTIVE и ролью
primary. Ограничения настоящего резерва и FENCED сохранены. Эти изменения
кода ещё не выпущены. Проверки: 25 тестов и 16 subtests прошли.

Полное автоматическое переключение рабочего сервиса пока НЕ включено:
нужны безопасное ограждение старого лидера, перенос рабочей базы, маршрутизация
и проверка единственного отправителя. GitHub-вход пока не завершён:
пользователь прервал device flow, затем получил 401 при вводе неверного токена.
Секреты в отчёт и Git не включены.

## Мобильная загрузка — 8 октября, вечер

Пользователь подтвердил пустую заставку Telegram на iPhone и зависание при
открытии домена в браузере. Полный мобильный вход пока НЕ подтверждён.
Обнаружена несогласованность: Caddy рекламировал HTTP/3 через Alt-Svc при
публикации только TCP-портов Docker и TCP-входах HAProxy. На рабочем прокси
после caddy validate и сохранения предыдущей конфигурации применены protocols
h1 h2 и Alt-Svc: clear, без перезапуска приложения. /healthz возвращает 200/ok.
Это подтверждённый дефект, но его связь с конкретным телефоном ещё проверяется.

Дополнительно устранены воспроизводимые сценарии бесконечной загрузки:
Telegram SDK больше не блокирует разбор HTML; независимый локальный watchdog
показывает восстановление при зависшем SDK, а bootstrap имеет тайм-аут 12с.
Проверка подписи Telegram сохранена. test_boot_loading.cjs воспроизводит
зависший SDK и API в мобильном размере окна, подтверждает сообщение и событие
снятия нативной заставки. npm test проходит. Эти изменения интерфейса ожидают
CI и штатного выпуска; в отличие от настройки Caddy они ещё не на сервере.

Первый штатный выпуск вернул приложение в рабочее состояние, но завершился
ошибкой: Docker Compose ожидал healthcheck у support, хотя этот воркер не
предоставляет HTTP endpoint и его healthcheck намеренно отключён. Исправление
release worker ожидает только health приложения, затем проверяет внешний
/healthz. До повторного выпуска результат не считать установленным.
