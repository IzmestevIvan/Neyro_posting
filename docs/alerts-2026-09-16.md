# Исправление алертов

Свежая проверка: девять emergency среди последних ста событий были повторными проверками ИИ; семь каналов публиковали за последние полчаса, failed/uncertain/partial не было. Срочность по трём событиям за час не отражала остановку работы.

Изменения:
- Повторные operations.ai сохраняются в файловом журнале и панели, но не повышаются до emergency по числу повторов. Без установленного журнала они тоже не отправляются напрямую в чат.
- Уведомления о доставке содержат номер поста и контекст канала. Перед отправкой читается текущий статус; опубликованные, истёкшие и другие уже не требующие сверки посты не порождают старый алерт.
- Различаются failed (не отправлен), partial (часть подтверждена) и uncertain (результат неизвестен). Для двух последних автоматический повтор запрещён, пользователь получает инструкцию сверить канал. Для failed указывается безопасная категория причины без частного текста/URL.
- Ошибки провайдера по тайм-ауту не называются падением приложения. Общий заголовок больше не утверждает необходимость вмешательства для каждого события.
- Критические сбои и повторные ошибки служебных циклов остаются в уведомлениях; само число повторов ИИ больше не используется как детектор остановки канала. Нового детектора длительной остановки ИИ это изменение не добавляет.

Тесты покрывают отсутствие спама после 30 повторов, актуализацию пяти статусов отправки, сохранение каждого события, редактирование секретов и повтор доставки самого алерта.
