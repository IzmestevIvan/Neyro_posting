## 2026-09-08 — первый этап критических исправлений

### Проверенные изменения

- PROMO-001/002: повтор своего кода не продлевает доступ и не откатывает лимиты. Новый код продлевает срок. Блокировки пользователя и кода в одной транзакции защищают от двух получателей и от потери одного из двух одновременных продлений.
- PROMO-004: лишние символы и суффикс кода не обрезаются. Разрешено только форматирование пробелами и дефисом.
- SEC-001/002: перед подключением проверяются роль человека и право бота публиковать. Ошибка Telegram не считается подтверждением прав.
- QUEUE-001: вставки постов и курсор сохраняются одной транзакцией. Параллельный устаревший опрос не перематывает курсор назад. Регрессия намеренно ломает вторую вставку и проверяет rollback первой.
- QUEUE-002: fingerprint текущего поста исключён из дедупликации.
- AI-001/002: недоступный, неполный, неверно типизированный или противоречивый фактчек не разрешает публикацию. Неверный триаж также блокирует дальнейший результат. Предупреждение не маскируется успешным ok.

### Дополнительные защиты, более широкие задачи ещё открыты

- Локальная тестовая фикстура отказывается от адресов вне localhost и БД с именем, отличным от neyro_test, а также от URL с query/fragment. Полная изоляция отдельной ограниченной ролью ещё требуется (QA-001).
- Общая проверка срока и блокировки добавлена к ручным событиям бота, обработке источников, ИИ и публикации. /start, /id, /help остаются доступными для восстановления входа. Для полного SEC-003/004 ещё нужна сквозная матрица всех событий и конкурентного отзыва.
- Отправка перечитывает пост под блокировкой, требует готовый text_out, не допускает статус new и не подставляет raw_text. Публикации без готового текста не выбираются кнопкой publish_now. Полное разделение типов ошибок и версий проверки ещё предстоит (POST-001).
- Reject не меняет опубликованные/отправляемые записи. Обновление черновика условно по исходному тексту и допустимому статусу; после регенерации сохраняется новый фактчек. Правки ответом в боте проходят проверку относительно исходника. Полная модель версий ещё предстоит (POST-002, API-008).
- Автоматический дайджест отключён при ручной модерации, истёкшем доступе и исчерпанной квоте. Карточка одобрения дайджеста и атомарный учёт публикаций ещё не реализованы (TIME-007/008/011).
- Сетевые ошибки httpx допускают резервную модель. Ключ передаётся заголовком, а не query-параметром; централизованное маскирование ошибок ещё нужно.

## 2026-09-09 — ложная реклама и действия архива

Подтверждена причина в коде: эвристика «рекламодатель» давала порог для мгновенного отклонения без контекста. Убран окончательный рекламный вердикт по одному score. Для кандидата из эвристики или AI-триажа добавлена отдельная проверка по исходному тексту. Ответ ad требует объяснения и дословной цитаты длиной не менее 8 символов, найденной в исходнике; промпт различает предложение купить и новости/критику рекламы. Проверка контекстная и вероятностная, не гарантия отсутствия ошибок.

При неопределённом результате/некорректной цитате успешный рерайт получает needs_review. Воркер не ставит такой материал в автопостинг или дайджест, а отправляет на ручное одобрение с причиной. При повторном рерайте тот же переход выполняется атомарно внутри replace_draft. Финальный фактчек по-прежнему обязателен в super; остальные причины отклонения остаются независимыми.

Архив: добавлены вкладки «На разбор / Архив», раскрываемая причина, действия «Это не реклама» и «Вернуть на разбор». API /channels/{id}/ads принимает view=active|archive; /ads/{id}/false_positive сохраняет пользовательскую оценку. Старые записи не удаляются и не переклассифицируются автоматически. ## 2026-09-09 — быстрое добавление источников

Реализованы два сценария: пересылка публичного канала боту с выбором «источник / публикация» и выборочное копирование между собственными каналами в разделе «Источники». Для пересылки пользователь выбирает канал назначения; доступность публичного предпросмотра проверяется перед сохранением. Скрытый/частный origin не угадывается: бот предлагает указать публичную ссылку в панели. Медиа без подписи можно использовать для добавления источника. Ручной пост запускает прежний pipeline только после выбора пользователя.

Состояние пересылки — один слот kv `forward:<user_id>`, случайный токен, срок действия 24 часа. Новая пересылка заменяет предыдущий выбор. Токен проверяется в контексте пользователя; ручной выбор атомарно потребляется до вызова AI. Слот содержит текст и Telegram file_id, не URL с токеном бота. Просроченное состояние не принимается (физически удаляется при следующей записи/потреблении). Список каналов в боте разбит по 20. Добавление повторно проверяет владельца в транзакции и использует ON CONFLICT.

POST `/api/channels/{target}/sources/copy`: `{from_channel_id: integer, source_ids: integer[]}`. Разрешено 1–500 выбранных ID, оба канала должны принадлежать пользователю, включая администраторов. Ответ `{added, skipped}`. Источники проверяются целиком до вставки; чужой/удалённый ID отменяет операцию. Каналы блокируются в одинаковом порядке; конкурентные повторы идемпотентны. Переносятся kind/ref/title; enabled=1, история курсора/ошибок/проверок не переносится. Уникальность по существующему ключу channel_id/kind/ref; семантически эквивалентные разные RSS URL не объединяются.

Проверки: интеграционные тесты PostgreSQL для конкурентных повторов, изоляции владельцев, атомарности и сброса истории; тесты устаревшего callback и однократного ручного выбора. Node syntax/state. Браузер: раскрытие раздела, выбор канала, загрузка и выбор источника, результат копирования на локальном API с фиктивными данными. Реальные Telegram сообщения при проверке не отправлялись.

Выпуск подтверждён: 185 Python-тестов прошли, проверки Node и git diff --check успешны. После Docker-деплоя app/db healthy, Caddy running, /healthz = 200. На визуальной проверке исправлены внутренние отступы карточки копирования; исправление включено в финальный деплой.

## 2026-09-09 — исправление остановившегося постинга

Диагностика рабочей базы: в канале нет новых/готовых постов, 57 failed и 77 filtered; 35 старых отказов прямо содержат `failed to get HTTP URL content`, ещё 6 — `WEBPAGE_CURL_FAILED`. Последние попытки также завершались TelegramBadRequest без подтверждений доставки. У бота статус administrator и can_post_messages=true в обоих каналах; доступ владельца активен. Две фотографии последних неудачных постов загружаются сервером с HTTP 200 (38 101 и 68 785 байт). Основная и проверочная модели на старте отвечают 429, резервная отвечает успешно.

Исправление медиа: внешние HTTP(S) вложения предварительно загружаются через существующий safe_http (проверка публичных адресов, DNS pinning, ограничение редиректов/времени/размера/MIME). Затем передаются как BufferedInputFile; подписанные CDN URL больше не передаются загрузчику Telegram. Все вложения альбома готовятся до первой отправки. Операционные ограничения приложения: 10 МиБ на изображение, 32 МиБ на видео, 64 МиБ на пост, 45 секунд на загрузку; общий дедлайн отправки остаётся 180 секунд. Существующие file_id не загружаются повторно. Вложения сверх этих ограничений не отправляются; текст автоматически не публикуется отдельно вместо отсутствующего медиа. Причина TelegramBadRequest теперь сохраняет текст отказа, а не только имя исключения.

Исправление обработки: отдельный запрос фактчека может использовать резервную модель и по-прежнему валидирует строгий вердикт. Это отдельный проверочный запрос, но при сбое основных моделей генератор и проверяющий могут использовать одно имя резервной модели. Проверка не пропускается. Недоступный триаж/фактчек и AIError оставляют пост new с publish_at через 15 минут; цикл обработки учитывает этот срок. Они не увеличивают счётчик редакционных отсеиваний. Недоступная повторная проверка также откладывается. После успешной обработки срок повторной проверки заменяется расписанием либо очищается. «Опубликовать сейчас» среди failed выбирает свежий пост, чтобы старый неудачный материал с истёкшими ссылками не блокировал остальные.

Исторические отказы/отсеивания не возвращаются массово в автопубликацию: это вызвало бы поток старых новостей. Готовые failed остаются доступны существующей кнопке немедленной публикации. Для новых материалов восстановлена обработка и повторная проверка. Реальные тестовые сообщения в каналы не отправлялись.
