# Интерфейс редакции

## Визуальные решения

Светлая тема: тёплый нейтральный фон, белые поверхности, графитовый текст и синий акцент.
Тёмная: глубокий зелёный фон и светлый текст. Выбор следует настройке Telegram/браузера;
в шапке можно вручную выбрать тему и RU/EN. Шрифты системные, иконки — существующий SVG-спрайт.
Главная без канала использует крупный заголовок, тонкие разделители и три последовательных
шага, без вымышленных постов и статистики.

Навигация содержит «Главная / Посты / Источники / Настройки»: слева от 1080 px,
снизу на меньших экранах. Три основных счётчика объединены общей рамкой. Кнопки имеют
достаточную высоту для касания; настройки сгруппированы в раскрывающиеся разделы.
Reduced-motion отключает анимации, клавиатурный фокус остаётся видимым.

## Просмотр без канала

После активации промокода или платного доступа на экране подключения есть кнопка
«Пропустить — изучить приложение». Доступны главная, публикации/история, источники,
обзор настроек, тариф и полное обучение. Канал можно подключить позднее из шапки,
главной или пояснения в разделе.

Выбор сохраняется локально под `neyro:explore:<tg_id>` отдельно для аккаунта. Если
хранилище недоступно, пропуск работает в текущем сеансе; повторный вход снова предложит
подключение. Наличие канала всегда имеет приоритет над сохранённым пропуском.

Пропуск не выдаёт доступ и не создаёт канал. Без активного доступа остаётся экран
активации. В режиме просмотра запросы к данным канала не отправляются; настройки и
добавление источников доступны для ознакомления без сохранения. Панели ввода списка
источников и копирования можно раскрыть. Публикация требует настоящего канала.
После подключения контролы восстанавливаются; обновление тарифа также подхватывает
канал, подключённый на другом устройстве.

## Главная и готовность публикации

Карточка следующего шага выбирается по приоритету: нет источников → сбор на паузе → есть посты на проверке → источники подключены. Статистика показывает опубликованное сегодня, ожидающие проверки и остаток общей квоты аккаунта; график подписчиков — в раскрываемой аналитике.

API stats добавляет ready: количество записей в approved/pending/digest/failed с непустым text_out. Это согласовано с выборкой publish_now; raw/new и уже опубликованные записи не считаются готовыми. Готовность — снимок, а не резервирование: сервер заново проверяет пост и квоту при отправке.

Publish now поясняет немедленную отправку одного поста мимо расписания/паузы. При пустой очереди или исчерпанной квоте кнопка недоступна с объяснением. Во время запроса флаг publishingNow предотвращает повторное включение кнопки фоновым обновлением статистики. Суточная квота общая для всех каналов аккаунта; её серверный учёт описан в [billing.md](billing.md).

## Публикации

Переключатель «На проверке / История» использует существующие API feed/history. У действий есть подписи: «Опубликовать», «Переписать», отдельная доступная подпись для отклонения. После рерайта перечитывается вся карточка, чтобы вердикт не оставался от старого текста. Нет text_out — публикация недоступна.

Фактчек имеет три отображения: успешная проверка, замечания, отсутствие финальной проверки. Успех не обещает абсолютную достоверность. История показывает статус, превью, причину и время; она ограничена последними 50 событиями, очередь — 30 постами. Полная пагинация пока отсутствует. Внешние ссылки в постах и архиве пропускают только HTTP(S) и открываются с noopener/noreferrer.

## Настройки и конкурентность

Все PATCH-запросы проходят через saveQueue. ID канала фиксируется при постановке изменения в очередь. Обновление boot.channels применяется по этому ID. Выбор/добавление канала блокируются до завершения очереди. Индикатор сообщает сохранение, успех или ошибку.

Несохранённый текст хранится в Map с ключом channelId:field. Введённый текст подставляется обратно при возврате к каналу. Успешное сохранение очищает только совпадающий черновик; более новый ввод не удаляется. Это память вкладки, не долговременное хранилище. Ошибка переключателя/часа откатывает соответствующий контрол, не стирая соседние текстовые поля.

Чтения используют счётчик запросов по разделу и зафиксированный channel ID. Ответ применяется только если он всё ещё последний и канал совпадает; переключение канала инвалидирует счётчики. Это касается ленты, рекламы, источников, истории и статистики. Запросы не отменяются, но их устаревшие результаты не рисуются.

## Изменение контракта PATCH

Булевы поля требуют настоящие JSON true/false. Строки «false», «да», пустые строки, числа и null отклоняются с 422. Часы должны быть целыми в диапазоне 0–23 / 1–24; строковый целый час допускается для HTML input. Дайджест принимает строго ЧЧ:ММ, 00:00–23:59. Неверные enum и неизвестные поля отклоняют запрос целиком. Клиент показывает строковое объяснение ошибки.

## Проверка и ограничения

`tests/test_explore_ui.cjs` запускает приложение с перехваченными API-ответами:
активация кода с перезагрузкой, пропуск, навигация без канала, обновление тарифа,
сохранение выбора, подключение, канал с другого устройства и истечение доступа.
Проверяется отсутствие запросов к каналам до подключения и отсутствие лишних записей.
64 снимка покрывают четыре ширины, оба языка и темы.

`tests/visual_smoke.cjs` проверяет ещё 192 состояния действующего канала, тарифа,
кабинета, учебника и экранов входа. Проверяются переполнение, размеры кнопок и ошибки JS.
Учебник отдельно проверяет клавиатуру, сохранение прогресса и переходы.
Скрипты используют Playwright и вымышленные данные; они не публикуют посты и не оплачивают
тариф. Это не проверка всех реальных Telegram WebView и не подтверждение живого платежа.
