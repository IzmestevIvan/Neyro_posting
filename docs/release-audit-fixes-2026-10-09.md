# Исправления аудита 9 октября 2026

## Подготовлено

- Отказ выпуска и rollback при остановке/перезапуске support; оба worker должны
  оставаться здоровыми в течение проверочного интервала.
- Строгая проверка формата подписи Telegram: некорректный hash возвращает 401.
- boot.js включён в версию статических файлов.
- Независимый минутный монитор на обоих edge-узлах с существующими адресатами,
  подавлением кратких сбоев и повторов. На neyro_de также проверяются возраст
  успешной копии, таймер и место. Он не запускает и не переключает приложение.
- Резервная копия включает точные образы app/Caddy, сохранённые также зашифрованными.
  Проверяются импорт приложения, конфигурация Caddy, восстановление БД и HTTP/API
  в восстановленном образе без внешней сети, отправок и миграций.
- Клиентский адрес проходит от HAProxy к Caddy через PROXY v2; доверяются только
  два адреса edge. Заголовки X-Forwarded-For посетителя по-прежнему перезаписываются.
  Использован встроенный [listener Caddy](https://caddyserver.com/docs/caddyfile/options#proxy-protocol).

## Порядок установки

После успешного CI: установить исправленный root-owned release worker на primary,
слить изменения и запустить штатный GitHub Deploy для точного main SHA. Отдельными
Ansible playbooks применить ha-backups.yml, ha-monitor.yml и ha-proxy-identity.yml.
Последний сначала валидирует и загружает Caddy с откатом конфигурации при ошибке,
затем включает передачу адресов на HAProxy. Не применять legacy site.yml.

## Не подменять этими исправлениями

Полный автоматический failover рабочего приложения, независимое от VPSPay
immutable-хранилище и ручная сверка uncertain/recovery_hold остаются отдельными
операциями. Самовольная повторная отправка неизвестных публикаций недопустима.
Ни монитор, ни процедура проверки копий не активируют второго бота.

Результаты фактической установки будут записаны после выпуска.
