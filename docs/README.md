## Правила для тех, кто правит код

1. **Новая колонка — две записи.** И в `SCHEMA`, и в `MIGRATIONS` в `app/db.py`.
   Иначе на существующей базе всё упадёт с «column does not exist».
   Для платежей и веб-сессий схемы отдельно в `app/billing/schema.py` и
   `app/api/account_auth.py`; `db.connect()` применяет их идемпотентно.
2. **Порог фильтра меняется вместе с тестами.** В `tests/test_filters.py` лежат наборы
   настоящей рекламы и настоящих новостей. Правка весов, после которой новость
   про рекламный рынок снова отсеивается, — регресс.
3. **Не резать экранированный текст.** Только через `_fit_escaped()`, иначе Telegram
   отклонит сообщение с ошибкой разбора сущностей.
4. **Имена колонок не приходят из запроса.** Любое поле, попадающее в `UPDATE`, сначала
   проходит белый список `_clean_settings()`.
5. **`DEV_AUTH` — только локально.** На сервере переменной быть не должно.
6. **Вставка с возвратом id — только `db.insert()`.** У `users`, `kv` и `stats_daily`
   нет колонки `id`, и `RETURNING id` на них падает.
7. **Ручки с каналами — за `active_user`.** `current_user` только опознаёт, доступ по
   промокоду проверяет `active_user`.
8. Перед деплоем: `.venv/bin/python -m pytest tests/ -q` (нужен локальный PostgreSQL).
