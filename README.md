# Нейропостинг

Телеграм-бот с мини-приложением: берёт контент из заданных источников, переписывает нейросетью,
отсеивает рекламу/дубли/оффтоп, публикует по расписанию. Вторая модель проверяет первую на выдумки.

Подробная техническая документация — в [docs/](docs/README.md): архитектура, модель
данных, конвейер обработки, справочник API, эксплуатация и журнал принятых решений.

План дальнейших работ — [подробный TODO](docs/TODO.md): 252 задачи с приоритетами,
основаниями в коде и критериями проверки.

## Запуск

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.lock
createdb neyro                      # нужен PostgreSQL 16+
cp .env.example .env                # BOT_TOKEN, ADMIN_IDS, GEMINI_API_KEY, DATABASE_URL
.venv/bin/python -m app.main
```

Поднимаются одновременно: long-polling бота, HTTP-сервер мини-приложения на `PORT` и фоновые задачи опроса источников, подготовки и публикации постов, дайджеста,
статистики, сверки платежей и служебных уведомлений.

### Мини-приложение

После активации доступа подключение канала можно пропустить и изучить разделы, настройки
и обучение. Канал понадобится для добавления источников и публикации. Тема и язык
следуют настройкам клиента, доступны ручные переключатели. Подробнее: [интерфейс](docs/interface.md).

Telegram открывает Web App только по HTTPS. Локально:

```bash
ngrok http 8080
```

Полученный адрес положить в `PUBLIC_URL`, его же указать в @BotFather → Bot Settings → Menu Button.

Для отладки в обычном браузере, без Telegram: `DEV_AUTH=1` в `.env`, затем
`http://localhost:8080/?dev=<ваш_tg_id>`. **В продакшене DEV_AUTH обязательно убрать** — он
пропускает любого, кто подставит чужой id.

## Продакшен

Основной стек на VPS с Ubuntu 24.04 состоит из четырёх контейнеров:

- `db` — PostgreSQL 16, наружу не смотрит вообще;
- `app` — бот и API, слушает 8080 только внутри docker-сети;
- `caddy` — HTTPS-фронт на 80/443, получает и продлевает сертификат;
- `support` — отдельный бот поддержки.

Основной адрес — **https://flipbazar.ru**. Mini App доступен по `/`, самостоятельный
личный кабинет — по `/account`. Старый технический адрес не является адресом кабинета.
Описание защиты и резерва: [security-defense.md](docs/security-defense.md),
[disaster-recovery.md](docs/disaster-recovery.md).

GitHub CI/CD и Ansible подготовлены в `codex/infrastructure-baseline`; их подключение
ещё не завершено. Точный статус, запуск проверок и порядок настройки:
[инфраструктура](docs/infrastructure.md). Kubernetes подготовлен для будущего переноса
и не устанавливается на текущие VPS.

После подключения выпуска используйте GitHub → Actions → **Deploy production**
с полным SHA проверенного main-коммита, либо `./deploy.sh <sha>` через GitHub CLI.
Скрипт больше не загружает незакоммиченную рабочую папку. Деплой сохраняет закрытые
настройки сервера, делает снимок и откатывает приложение при ошибке запуска.
Секреты платежей, ботов и базы не должны попадать в Git или браузерные ассеты.

Полезное на сервере:

```bash
cd /opt/neyro
docker compose logs -f app     # живой лог
docker compose up -d app       # пересоздание после правки .env
docker compose down            # остановить всё
```

База живёт в docker-томе `pgdata`, логотипы — в `/opt/neyro/data`. И то и другое переживает
пересборку образа.

## Как устроено

| Слой | Файлы | Задача |
|---|---|---|
| Источники | `app/sources/` | `telegram_web` читает публичное превью `t.me/s/<канал>` (текст, фото, видео, просмотры), `rss` — ленты, `web` — обычные страницы для ручных постов |
| Фильтры | `app/core/filters.py` | стоп-слова, эвристики рекламы, дедуп по Жаккару, чистка хвостов чужого канала |
| ИИ | `app/ai/` | триаж (реклама/оффтоп) → рерайт → фактчек второй моделью; при отказе основной модели уходит на резервную и ставит её на паузу |
| Планировщик | `app/core/scheduler.py` | опрос, конвейер, окно публикации, темп, дайджест, статистика, недельный отчёт |
| Публикация | `app/core/publisher.py` | отправка в канал, подпись-ссылка, водяной знак, дневные лимиты |
| Бот | `app/bot/` | карточки модерации, ручные посты, правки ответом на карточку, загрузка логотипа |
| Доступ | `app/core/promo.py`, `app/billing/` | коды доступа, подписки, расчёт доплаты и сверка платежей |
| Рекламодатели | `app/core/adbook.py` | отсеянная реклама с контактами — база для прямых продаж |
| API + панель | `app/api/`, `app/miniapp/` | Mini App с initData и самостоятельный кабинет с Telegram Login и cookie-сессией |

Хранилище — PostgreSQL. Мультиарендность: у каждого канала есть `owner_id`, все запросы
панели проверяют владельца; админ из `ADMIN_IDS` видит сводку по всем.

Доступ даёт оплаченная подписка или действующий код. В Mini App показывается уже
приобретённый доступ; ЮKassa используется в самостоятельном веб-кабинете.

| Подписка | Цена в месяц | Публикаций в сутки на весь аккаунт |
|---|---:|---:|
| PLUS | 390 ₽ | 5 |
| PRO | 490 ₽ | 10 |
| EXPERT | 590 ₽ | 15 |
| CREATOR | 990 ₽ | 25 |
| UNLIMITED | 1490 ₽ | 50 |

Продление ручное, без автосписаний. Повышение — после доплаты за остаток периода;
понижение выбирается на следующий период. Дневной лимит обновляется в 00:00 UTC.
MINI, «копирование контент-плана» и «репостер» отсутствуют. Бизнес-режим временно
отключён; существующие данные сохраняются. Старые пресеты промокодов не являются
каталогом платных подписок.

Параметры запуска, проверка ЮKassa и чеки самозанятого описаны в
[billing.md](docs/billing.md). Наличие реализации и прохождение тестов не подтверждают
проведение реального платежа; фактический статус запуска фиксируется отдельно.

## Режимы качества

| Режим | Запросов к ИИ | Что делает |
|---|---|---|
| Быстро | 1 | лёгкий рерайт, реклама отсеивается только регулярками |
| Баланс | 2 | + отсев рекламы и оффтопа нейросетью |
| Суперпостинг | 3–5 | + глубокий рерайт с контекстом и фактчек второй моделью; при провале — один повтор на низкой температуре |

## Подключение канала

1. Добавить бота администратором канала с правом публикации.
2. В панели нажать `+` и ввести `@username` канала.
3. На вкладке «Источники» добавить каналы-доноры или RSS.

## Что бот понимает в личке

- ссылка на пост `t.me/...` или любая веб-страница — ручной пост;
- просто текст — ручной пост из этого текста;
- фото или видео с подписью — пост вместе с медиа;
- ответ на карточку словами вроде «короче», «без эмодзи» — перепишет;
- картинка с подписью «логотип» — сохранит водяной знак.

## Страницы панели

Главная · Посты (проверка и история) · Источники · Настройки · Мой тариф.
Реклама доступна из раздела постов. Админ-панель видна только администраторам.

Тема: системная, светлая или тёмная. Язык интерфейса: автоматически, русский или
английский; он не меняет язык постов и пользовательские тексты. Параметры хранятся
локально в браузере. «Как работает Нейропостинг» открывает учебник из восьми тем
с сохранением прогресса, доступный даже до подключения канала.
